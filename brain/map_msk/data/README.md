# Данные тренажёра улиц ЦАО

`cao-map.json` — локальный снимок OpenStreetMap для статической страницы
GitHub Pages. Во время игры сеть не используется: районы, улицы, граница ЦАО и
Москва-река уже находятся в файле.

Текущий снимок:

- версия: `osm-20260725111701-e4291ab624e1`;
- время данных OSM: `2026-07-25T11:17:01Z`;
- ЦАО: relation `2162196`, Wikidata `Q190412`;
- 10 районов;
- 1 030 улиц;
- 1 986 однозначных вариантов ответа;
- 1 417 компонент уличных линий, 5 244 координаты после упрощения;
- 113 улиц проходят более чем по одному району;
- 36 неоднозначных сокращённых вариантов исключены и перечислены в
  `street_alias_collisions.json`;
- размер `cao-map.json`: 554 495 байт.

## Контракт `cao-map.json`

На верхнем уровне всегда находятся четыре поля:

- `meta` — версия схемы и набора, bbox, параметры сборки и происхождение;
- `districts` — десять полигонов районов;
- `streets` — улицы с `id`, `name`, `kind`, `aliases`, `districtIds`,
  `quizDistrictId`, `highwayTypes` и `MultiLineString`;
- `context` — массив из `cao-boundary` и `moskva-river`.

Координаты имеют порядок `[longitude, latitude]`, CRS — `EPSG:4326`.
`datasetVersion` детерминирован временем исходного снимка и SHA-256
канонического содержимого набора без самого поля версии.

`districtIds` хранит все районы, по которым проходит улица.
`quizDistrictId` нужен для единственного столбца в квизе и выбирается по
наибольшей длине улицы внутри района.

`kind` извлекается из названия (`улица`, `переулок`, `площадь`, `проспект`,
`мост` и так далее); для названий без явного типа используется `дорога`.
Исходные классы OSM не теряются и остаются в `highwayTypes`.

## Воспроизводимая сборка

Скрипт не требует `pip`, npm или системных GIS-библиотек:

```bash
python3 brain/map_msk/tools/build_cao_map.py \
  --raw-dir /tmp/kirilldikalin-cao-osm-YYYYMMDD \
  --refresh
```

В `--raw-dir` сохраняются три ответа Overpass и соответствующие
`.overpassql`-файлы. Повторная сборка из ровно того же сырья не обращается к
сети и даёт побайтово тот же результат:

```bash
python3 brain/map_msk/tools/build_cao_map.py \
  --raw-dir /tmp/kirilldikalin-cao-osm-YYYYMMDD \
  --offline
```

Отдельная проверка уже собранного файла:

```bash
python3 brain/map_msk/tools/build_cao_map.py \
  --validate-only brain/map_msk/data/cao-map.json
```

Валидатор останавливает сборку при неизвестном или пропавшем районе, пустой
геометрии, повторяющемся ID, пустом `kind`, неизвестном `districtId`,
невалидном `quizDistrictId`, ненормализованном или повторяющемся алиасе.

## Запросы Overpass

Сначала ЦАО находится по стабильному Wikidata ID, а районы — внутри его area.
Relation ID намеренно не используется для поиска: прежние ID ЦАО `364005` и
Басманного района `1257201` уже удалены из OSM.

```overpass
[out:json][timeout:120];
rel
  ["boundary"="administrative"]
  ["admin_level"="5"]
  ["wikidata"="Q190412"]
  ->.cao;
.cao map_to_area ->.cao_area;
(
  .cao;
  rel(area.cao_area)
    ["boundary"="administrative"]
    ["admin_level"="8"];
);
out tags qt;
```

После проверки, что найдено ровно десять ожидаемых районов, скрипт подставляет
их актуальные relation ID в запрос геометрии. Для текущего снимка запрос был:

```overpass
[out:json][timeout:180];
rel(id:364001,1255942,1255987,1257218,1257484,1257786,1275551,1275608,1275627,2162195,2162196);
out body geom qt;
```

Улицы запрашиваются по bbox найденного ЦАО, а затем точно обрезаются его
полигоном. Запрос через bbox нужен, чтобы не потерять длинный way, который
пересекает ЦАО, но не имеет вершины внутри area.

```overpass
[out:json][timeout:300];
(
  way(55.7102802,37.5139298,55.7971703,37.7135295)["highway"]["name"];
  way(55.7102802,37.5139298,55.7971703,37.7135295)["waterway"="river"]["name"="Москва"];
);
out body geom qt;
```

Числа bbox при следующей сборке вычисляются заново.

## Правила очистки

Самостоятельными ответами становятся именованные линии:

- `motorway`, `trunk`, `primary`, `secondary`, `tertiary`;
- `unclassified`, `residential`, `living_street`;
- `pedestrian`.

`service`, `footway` и дорожные `*_link` могут дополнить геометрию уже
существующей улицы, но сами не создают ответ. `construction`, `proposed`,
безымянные и прочие служебные линии исключаются.

После классификации имени в квиз допускаются только улицы, переулки,
проспекты, бульвары, набережные, проезды, площади, шоссе, тупики, аллеи,
линии и просеки. Мосты, путепроводы, тоннели, эстакады, ворота и названия
дорожных колец не являются отдельными ответами.

Уличные линии:

1. обрезаются точным мультиполигоном ЦАО;
2. объединяются по нормализованному имени;
3. отбрасываются, если после обрезки короче 20 метров;
4. упрощаются с допуском 5 метров;
5. пересекаются с каждым районом для `districtIds` и `quizDistrictId`.

Три пограничных фрагмента короче 20 метров не вошли в набор:
`2-й Воспитательный проезд`, `Лефортовская площадь`, `шоссе Энтузиастов`.
Они находятся в `droppedShortStreets` отчёта.

Восемь OSM-названий с пометкой `(дублёр)` переименовываются в основную улицу:
их линии сохраняются, но отдельного ответа не возникает. Девять технических
`проектируемый проезд No ...` и десять объектов неподходящих типов явно
исключены через `street_overrides.json`. Валидатор дополнительно запрещает
выход `(дублёр)`, проектируемых проездов и неподдерживаемых `kind` в итоговый
файл.

Москва-река — осевая линия OSM. Она намеренно обрезается bbox, а не полигоном
ЦАО: на участках, где река образует административную границу, её ось лежит
формально снаружи округа и иначе исчезла бы с карты.

## Алиасы и ручные исправления

Допустимые ответы нормализуются: регистр, `ё`/`е`, пробелы и варианты дефиса.
Используются текущие `name`, `alt_name`, `official_name`, `short_name`,
`loc_name`. Исторический `old_name` автоматически не принимается.

Название без типа улицы добавляется только тогда, когда оно однозначно.
Например, `Покровка` можно принять вместо `улица Покровка`, но `Болотная`
нельзя автоматически отнести к площади, улице или набережной. Все 36 таких
случаев находятся в `street_alias_collisions.json` и не попадают в `aliases`.

Ручные исключения, принудительные включения, переименования и дополнительные
ответы задаются в `street_overrides.json`. Неоднозначный ручной алиас также
будет остановлен валидатором.
