# Алгоритмический атлас

Атлас — самостоятельный статический раздел сайта. Он использует HTML, локальные
CSS/JavaScript-файлы и машиночитаемые JSON-описания. Бэкенд, сборщик, регистрация
и библиотека визуализации не нужны.

> **Канонический учебный граф:** [`docs/curriculum.md`](docs/curriculum.md).
> Перед планированием новой главы или изменением маршрутов необходимо полностью
> прочитать этот документ и сверить идентификатор, материк, порядок и разрешённые
> переходы. `atlas-graph.json` хранит только оперативные статусы реализации.

## Локальный просмотр

Страницы атласа загружают граф и реестр обозначений через `fetch`, поэтому
открытие HTML напрямую по адресу `file://` не поддерживается браузерами. Запустите
из корня репозитория простой локальный сервер:

```shell
python3 -m http.server 8765 --bind 127.0.0.1
```

После этого откройте
`http://127.0.0.1:8765/algorithmic_atlas/`. Такой просмотр соответствует работе
статического сайта на GitHub Pages; отдельная сборка не требуется.

## Источники истины

- `data/atlas-graph.json` описывает материки, маршруты, узлы и связи
- `data/math-notations.json` хранит явный реестр математических обозначений
- статический `<ol>` внутри `.atlas-chapter-toc` задаёт смысловые разделы главы
- математические ядра лабораторий находятся в `labs/*-core.js`

`atlas-core.js` проверяет граф и вычисляет порядок маршрута, доступ, прогресс и
признаки контента. `atlas.js` только отображает эту модель. Порядок объектов в
массивах JSON не имеет смысла и не должен влиять на интерфейс.

## Модель карты

Схема графа имеет версию 2.

Материк содержит:

- стабильный `id`, название и короткое описание без точки в конце
- `publication: "published" | "planned"`
- `allowFreeExplore`
- обязательные `prerequisites` и дополнительные `related`
- `worldPosition`, `worldSize` и вариант формы для общей карты
- локальную карту и области только тогда, когда материал материка опубликован

Узел содержит:

- стабильный `id`, название, описание, тип, материк и область
- независимое состояние публикации
- обязательные и дополнительные связи
- локальный URL только для опубликованного материала
- время изучения и координаты на локальной карте
- фактические признаки `features.proof`, `features.interactive`,
  `features.exercises`

Плановый узел не имеет URL и не заявляет доказательство, лабораторию или
упражнения. Признак можно включать только при наличии соответствующего блока в
HTML. Эти признаки нужны валидатору и внутренней модели, но не отображаются
отдельными плашками в карточках или кратких представлениях главы.

## Маршруты и ветвления

`routes` задаёт навигационный порядок явно:

```json
{
  "id": "origins-main",
  "scope": "nodes",
  "kind": "main",
  "continentId": "origins-efficiency",
  "entries": [
    { "nodeId": "before-computers", "position": 10 }
  ]
}
```

Позиции уникальны внутри маршрута. Используются интервалы `10, 20, 30`, чтобы
вставка точки не требовала перенумерации всего пути.

У атласа есть ровно один основной маршрут материков. У материка с узлами есть
один или несколько явно упорядоченных основных маршрутов глав; несколько
маршрутов нужны, когда области материка изучаются параллельно. Рендерер находит
их по `scope`, `kind`, `continentId` и `position`, а не по конкретной строке ID.
Прогресс ядра объединяет узлы всех основных маршрутов без неявного перехода от
конца одной области к началу другой.

`prerequisites` образуют настоящий ориентированный ациклический граф.
Ответвление начинается узлом, зависящим от общей предыдущей точки. Слияние
ветвей задаётся несколькими обязательными зависимостями у следующего узла.
`related` показывает полезную тропу, но не управляет доступом.

### Окончательный маршрут «Истоки и эффективность»

Материк содержит ровно пять глав:

1. Что люди называли алгоритмами до появления компьютеров
2. Алгоритм Евклида
3. От ручного вычисления к машине Тьюринга
4. Размер входа и стоимость вычисления
5. Асимптотические оценки

После пятой главы маршрут материка завершён. Навигация возвращает читателя на
общую карту и показывает следующий материк — «Математические инструменты».
Материк считается пройденным, когда завершены все пять опубликованных глав.

### Реализованный материк «Математические инструменты и анализ»

Состав материка определяется `docs/curriculum.md` и содержит ровно 11 глав.
Восемь глав образуют обязательное ядро:

```text
2.1 → 2.2 → 2.3 → 2.4 → 2.5 → 2.9 → 2.10 → 2.11 → 3.1
```

Это главы `growth-rates`, `sums-products-recurrences`,
`sets-relations-functions-logic`, `proof-methods-induction`,
`correctness-invariants-termination`, `computation-models`, `analysis-cases` и
`polynomial-efficiency`. Прохождение всех восьми глав ядра завершает основной
маршрут материка и открывает переход к `3.1` «Абстрактные типы данных и
линейные структуры» независимо от прохождения дополнительной ветви.

Дополнительная вероятностная ветвь зафиксирована отдельно:

```text
2.3 ⇢ 2.6 → 2.7 → 2.8 ⇢ 7.1
```

В неё входят `combinatorics-counting`, `probability-spaces` и
`random-variables-concentration`. Последняя точка показывает содержательное
продолжение в `7.1` «Модели рандомизированных алгоритмов», но ветвь не является
условием открытия третьего материка.

Прогресс материка имеет две независимые характеристики:

- **ядро** — число завершённых глав из 8; значение `8 / 8` разрешает переход к
  следующему материку
- **полный прогресс** — число завершённых опубликованных глав из 11; значение
  `11 / 11` означает 100% прохождения материка

Интерфейс локальной карты показывает ядро и ветвь раздельно. Нельзя считать
`8 / 8` полным прохождением или, наоборот, требовать ветвь для перехода к
`3.1`.

### Реализованный материк «Структуры данных»

Материк содержит ровно 13 глав из `docs/curriculum.md`. Семь глав образуют
обязательное ядро:

```text
3.1 → 3.2 → 3.3 → 3.5 → 3.6 → 3.7 → 3.9 → 4.1
```

Это `linear-data-structures`, `hash-tables`, `balanced-search-trees`,
`priority-queues-heaps`, `disjoint-set-union`, `b-trees-external-memory` и
`range-query-structures`. Завершение всех семи открывает переход к `4.1`, но
не означает 100% прохождения материка.

Шесть дополнительных глав распределены по пяти ветвям:

```text
3.3 ⇢ 3.4
3.2 ⇢ 3.8 ⇢ 7.3
3.9 ⇢ 3.10 → 3.11 ⇢ 6.3
3.2 ⇢ 3.12 ⇢ 9.8
3.7 ⇢ 3.13 ⇢ 9.13
```

Ветви представлены отдельными маршрутами, поэтому пунктирный вход не
превращает внутреннюю обязательную связь `3.10 → 3.11` в необязательную.
Продолжения `6.3`, `7.3`, `9.8` и `9.13` пока представлены только метаданными:
их HTML-страницы ещё не существуют, и в прогрессе они не учитываются.

Локальная карта раздельно показывает:

- **ядро** — завершённые главы из 7; значение `7 / 7` открывает материк 04
- **ветви** — завершённые дополнительные главы из 6
- **полный прогресс** — завершённые опубликованные главы из 13; значение
  `13 / 13` означает 100% прохождения материка

Каждая глава использует общий runtime лабораторий, но хранит проверяемое
математическое ядро в собственном `labs/<slug>-core.js`. Общие стили
визуализаций материка находятся в `labs/data-structures-labs.css`.

### Реализованный материк «Методы построения алгоритмов»

Материк 04 содержит все 14 канонических глав из `docs/curriculum.md`. Каждая
глава опубликована с локальным URL, метриками чтения, проверяемым математическим
ядром лаборатории и фактическими признаками контента. В свободном режиме все
главы доступны; последовательный режим следует обязательным зависимостям.

Основное ядро содержит девять глав:

```text
4.1 → 4.2 → 4.3 → 4.4 → 4.5 → 4.7 → 4.9 → 4.11 → 4.12 → 5.1
```

Пять дополнительных глав распределены по четырём ветвям:

```text
4.5 ⇢ 4.6 ⇢ 5.5
4.7 ⇢ 4.8 ⇢ 6.5
4.1 ⇢ 4.10 ⇢ 8.9
4.12 ⇢ 4.13 → 4.14 ⇢ 7.13
```

Из `4.12` также показаны только предусмотренные учебным планом дополнительные
выходы к `8.4` и `8.14`. Карта делится на четыре области: поиск и декомпозиция,
порядок и жадный выбор, динамика и эвристики, формулировки и оптимизация.

Локальный прогресс раздельно показывает ядро `9 / 9`, ветви `5 / 5` и полный
итог `14 / 14`. Завершение ядра открывает канонический переход к `5.1`; шесть
других выходов пока остаются continuation-метаданными будущих материков.

### Реализованный материк «Графы, сети и оптимизация»

Материк 05 содержит все 14 канонических глав из `docs/curriculum.md`. Девять
глав образуют обязательное ядро:

```text
5.1 → 5.2 → 5.3 → 5.5 → 5.6 → 5.8 → 5.9 → 5.10 → 5.14 → 6.1
```

Пять дополнительных глав распределены по четырём ветвям:

```text
5.3 ⇢ 5.4
5.6 ⇢ 5.7
5.9 ⇢ 5.11
5.5 ⇢ 5.12 → 5.13
```

Завершение девяти глав ядра открывает канонический переход к `6.1`, но полный
прогресс материка становится равен `14 / 14` только после прохождения всех пяти
ветвей. Дополнительные выходы к `7.9`, `7.11`, `8.10`, `9.3` и `9.4` хранятся
как continuation-метаданные и не входят в прогресс.

Все графовые лаборатории используют общие `graph-lab-core.js`,
`graph-lab-runtime.js`, `graph-labs.css` и единый контракт управления. Главы
хранят только собственное математическое ядро и DOM-адаптер. Лаборатории
линейной алгебры и спектральных алгоритмов дополнительно разделяют одно
матричное ядро `graph-matrix-core.js`; различающиеся соглашения о допустимых
весах, петлях и положительной поддержке остаются в ядрах соответствующих глав.

### Реализованный материк «Строки, геометрия и численные алгоритмы»

Материк 06 содержит все 13 канонических глав и разделён на три области. Девять
глав ядра образуют три независимых основных маршрута:

```text
строки:               6.1 → 6.2 → 6.5
геометрия:            6.7 → 6.8
численные алгоритмы:  6.10 → 6.11 → 6.12 → 6.13 → 7.1
```

Четыре дополнительные главы распределены по трём ветвям:

```text
6.2 ⇢ 6.3 → 6.4
6.1 ⇢ 6.6
6.8 ⇢ 6.9 ⇢ 9.11
```

Связи `6.2 ⇢ 7.4` и `6.11 ⇢ 7.7` остаются метаданными будущего материка, а
переход `6.12 ⇢ 4.2` ведёт к уже опубликованной главе через `related`. Чтобы
открыть материк 07, необходимо пройти все девять глав ядра трёх областей;
четыре ветви не являются условием перехода. Полный прогресс `13 / 13` требует
завершить и ядро, и ветви.

Строковые лаборатории используют общий `sequence-lab-runtime.js` там, где
визуализация строится из последовательности символов, и общие стили
`strings-geometry-numerics-labs.css`. Геометрические главы разделяют точные
предикаты и систему координат из `geometry-lab-core.js`, runtime и стили.
Численные главы разделяют ограниченный playback, SVG-примитивы и правила
безопасного ввода из `numeric-lab-core.js`, `numeric-lab-runtime.js` и
`numeric-labs.css`. Математика каждой главы остаётся в собственном
`<slug>-core.js`.

`curriculumId` и стабильный технический `id` узла выполняют разные задачи.
Первый (`2.6`) связывает реализацию с каноническим учебным планом и отображается
на карте; второй (`combinatorics-counting`) используется в графе, URL, DOM и
локальном прогрессе. Их нельзя подменять друг другом или менять без отдельной
миграции и, для учебного идентификатора, изменения `docs/curriculum.md`.

Пока следующая глава ещё не реализована, конец маршрута описывается объектом
`continuation` внутри соответствующего `route`. Он содержит `curriculumId`,
`title`, `targetContinentId`, вид перехода `kind: "route" | "related"` и
координату `position` на локальной карте. Если из одной конечной точки есть
несколько дополнительных межматериковых связей, они перечисляются в
`relatedContinuations`; все элементы такого массива обязаны иметь
`kind: "related"`. Продолжение не является узлом, не имеет URL, не учитывается
в прогрессе и не должно дублировать существующий узел или другое продолжение.

Валидатор отклоняет:

- повторные позиции и повторные элементы маршрута
- отсутствующие маршруты, зависимости и связанные сущности
- циклы обязательных зависимостей
- несовпадение материка и области
- опубликованный узел без существующей страницы
- плановый узел с URL или заявленным контентом
- несовпадение `data-atlas-node-id` страницы и узла
- несовпадение `features` с реальными блоками главы

## Публикация, доступ и два вида тумана

Публикация хранится в JSON, доступ вычисляется:

- `published-unlocked` — материал опубликован и доступен
- `published-gated` — материал опубликован, но обязательный маршрут не пройден
- `planned` — материала ещё нет

Пройденность — отдельный визуальный признак, а не состояние публикации.

«Свободное исследование» открывает опубликованные узлы, у которых оно разрешено,
но не снимает туман с планового материала и не отмечает ничего пройденным. Режим
сохраняется вместе с прогрессом:

```text
{ schemaVersion: 2, datasetVersion, completedNodeIds, freeExplore }
```

Ключ `algorithmic-atlas-progress` и стабильные ID сохранены. Состояние схемы 1
автоматически переносится в схему 2. Неизвестная будущая версия не
перезаписывается старым кодом.

## Как добавить материк

1. Добавить объект в `continents` с уникальным ID и координатами общей карты.
2. Добавить его в маршрут уровня `scope: "continents"`.
3. Указать обязательные и дополнительные связи.
4. Оставить `publication: "planned"` и `localMap: null`, пока локального
   содержания нет.
5. После появления локальной карты добавить области, маршруты узлов и проверить
   все координаты.

## Как добавить главу

1. Создать HTML в `chapters/` на основе существующей страницы.
2. Подключить `chapter.css`, `atlas-core.js`, `chapter-core.js` и `chapter.js`.
3. Указать стабильный `data-atlas-node-id` на `<body>`.
4. Добавить статическое оглавление со ссылками на существующие уникальные ID.
5. Использовать блоки `data-atlas-block`: `definition`, `theorem`, `proof`,
   `history`, `example`, `lab`, `warning`, `exercises`, `sources`.
6. Добавить узел и явную позицию в маршруте.
7. Для опубликованной главы указать существующий `route`; для плановой —
   `route: null`.
8. Указать только реально существующие признаки контента.
9. Добавить страницу в `PUBLIC_PAGES` файла `scripts/check_site.py`.

Оглавление — доступный no-JavaScript fallback и единый источник разделов.
`chapter.js` использует тот же список для overlay-панели, активного якоря,
прогресса чтения и кнопок перехода вверх/вниз. Не создавайте второй список
разделов в JavaScript.

Основная статья остаётся геометрически центрированной. Оглавление раскрывается
поверх страницы, а не меняет ширину текста. На мобильном устройстве всегда
должна быть явная кнопка, не требующая наведения.

## Формулы и реестр обозначений

Строчные формулы не должны быть мельче предложения. Каждая блочная формула
помещается в `.atlas-math`: контейнер увеличивает формулу и даёт горизонтальную
прокрутку вместо автоматического уменьшения.

Символ `<` в HTML-формуле записывается как `&lt;`. Иначе HTML-парсер может
воспринять часть TeX как тег и визуально оборвать формулу.

Нельзя автоматически приписывать смысл произвольному TeX-символу. Для
интерактивного пояснения:

1. Добавьте запись в `data/math-notations.json`.
2. Укажите стабильный ID, отображаемое обозначение, короткое название,
   объяснение, область `global` или `local` и первое строгое определение.
3. Явно аннотируйте смысловой фрагмент внутри исходной формулы через
   поддерживаемое расширение MathJax `html`:

```html
<div class="atlas-math atlas-notation-formula">
  \[
    \class{atlas-notation-token notation-id-input-length}{|x|}
    =\text{число символов в коде }x.
  \]
</div>
```

`chapter.js` находит класс `notation-id-*` внутри результата MathJax и превращает
сам символ в клавиатурный и сенсорный триггер без отдельной строки, карточки или
изменения геометрии формулы. Аннотируются определения, теоремы и ключевые
переходы доказательств, а не каждое повторение символа. Локальное обозначение
можно использовать только в своей главе. Ссылка определения обязана вести на
опубликованную главу и существующий якорь.

Интерактивные фрагменты одной формулы не вкладываются друг в друга: каждый
`\class{atlas-notation-token ...}` охватывает отдельный смысловой символ или
выражение. Снимок `tests/formula-presentation-policy.json` должен охватывать все
опубликованные материки и обновляется только после полного формульного аудита.

## Типографика и интерфейсный текст

Полноценные абзацы, доказательства и содержательные пункты списков
выравниваются по ширине с русскими переносами. Заголовки, формулы, код, таблицы,
кнопки, оглавление, статусы и подписи элементов управления остаются
выровненными естественно. На узком экране повествовательный текст возвращается
к выравниванию по началу строки.

Редакционное правило:

- у короткой карточки, статуса, подписи, кнопки и пункта навигации нет точки
  в конце
- у полноценного предложения, абзаца, доказательства и многофразового
  пояснения пунктуация сохраняется

Правило применяется вручную по смыслу. Массово удалять точки нельзя.

## Требования к лабораториям

Лаборатория обязана:

- объяснять математический процесс визуально, а не только менять числа
- отделять точное вычислительное ядро от DOM-рендера
- использовать точную целочисленную арифметику там, где заявлены целые числа
- ограничивать геометрию и циклы на больших входах
- явно отмечать схематический или агрегированный масштаб
- синхронизировать число, формулу, таблицу и геометрию из одного состояния
- иметь доступные подписи SVG, клавиатурное управление и мобильный режим
- поддерживать `prefers-reduced-motion`
- отделять конечную численную иллюстрацию от доказательства для всего хвоста:
  статус «доказано» допустим только при отдельной аналитической проверке

Если есть автоматическое выполнение, обязательны отдельные «Один шаг»,
«Запустить», «Пауза» и «Сбросить» или «К началу». Ползунок скорости всегда
направлен одинаково: слева медленнее, справа быстрее. Пользователь видит
скорость в шагах в секунду, а задержка остаётся внутренней деталью.

Общий контракт скорости находится в `labs/lab-controls-core.js`:

```text
уровни 1..5 → 0,5; 1; 2; 4; 8 шагов/с
```

### Общий контракт лабораторий материка 02

Лаборатория подключается к пустому корневому элементу, а не хранит
продублированную разметку управления в странице:

```html
<div class="atlas-lab" data-atlas-lab="chapter-slug"></div>
```

Общие стили находятся в `labs/lab-common.css` и
`labs/mathematical-tools-labs.css`. Скрипты подключаются в одном порядке:

```text
lab-controls-core.js
mathematical-tools-core.js
lab-runtime.js
lab-svg.js
<chapter-slug>-core.js
<chapter-slug>.js
```

`*-core.js` — чистое UMD-ядро без DOM, пригодное для Node-тестов. Одноимённый
файл без суффикса `-core` — DOM-адаптер: он строит интерфейс внутри своего
`data-atlas-lab`, связывает управление с ядром и рисует визуализацию. Адаптер не
должен дублировать математику или хранить вторую версию состояния.

Для всех лабораторий материка обязательны следующие правила:

- пользовательские выражения не исполняются через `eval` или `Function`
- случайные сценарии используют явно передаваемое начальное значение генератора
  и воспроизводимую псевдослучайную последовательность
- целочисленные результаты вычисляются точной арифметикой; переход к численной
  аппроксимации подписывается явно
- запуск, пауза, один шаг, сброс и скорость используют общий контракт
  управления; у скорости слева всегда медленнее, справа быстрее
- автоматическое выполнение ограничено и не блокирует основной поток
- анимация учитывает `prefers-reduced-motion`, сохраняя пошаговое объяснение
- конечный эксперимент, график или симуляция иллюстрируют утверждение, но не
  получают статус доказательства без отдельной аналитической проверки

## Обязательные проверки

Перед добавлением или изменением главы:

```shell
python3 scripts/check_site.py
find algorithmic_atlas -name '*.js' -print0 | xargs -0 -n1 node --check
node --test algorithmic_atlas/tests/*.test.js
git diff --check
```

`check_site.py` проверяет страницы, ссылки, якоря, соответствие графа реальному
контенту, реестр обозначений, парность `\(...\)` и `\[...\]`, сырой TeX вне
математического режима и наличие `.atlas-math` у блочных формул.

Браузерный проход обязателен на широком экране, планшете и ширине 390 px, с
клавиатурой, сенсорным сценарием, светлой и тёмной системной темой и
`prefers-reduced-motion`. Нужно полностью прокрутить каждую изменённую страницу
и проверить консоль, MathJax, необработанный TeX, всплывающие обозначения у краёв
экрана, направление скорости, отсутствие горизонтального переполнения и
соответствие всех геометрий числовому состоянию.

Для материка 02 дополнительно проверяются все 11 HTML-страниц, их чистые
`*-core.js` и DOM-адаптеры. У каждой страницы должны совпадать `curriculumId`,
стабильный slug, `data-atlas-node-id`, локальный URL и фактические признаки
контента. Для каждого математического ядра выполняются синтаксическая проверка
